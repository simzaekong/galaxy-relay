# iPhone 설치

1. iOS 16.4 이상에서 Safari로 배포된 HTTPS 주소를 연다.
2. Safari 공유 → 홈 화면에 추가. 이름은 Galaxy Relay 또는 Relay로 둔다.
3. 홈 화면 아이콘으로 PWA를 실행한다. Safari 일반 탭에서는 iPhone Web Push를 사용할 수 없다.
4. Galaxy 앱에서 만든 12자리 연결 코드를 입력하고 연결한다.
5. PWA에 표시되는 승인 코드를 Galaxy 앱의 “연결 상태 확인” 화면과 비교하고 Galaxy에서 승인한다.
6. PWA의 새로고침을 누른다. KV 전파 때문에 최초 연결이 잠시 지연될 수 있다.
7. 설정 → “이 기기 알림 활성화”를 직접 누르고 권한을 허용한다. 준비 중에는 버튼이 비활성화된다.
8. Galaxy 앱에서 “테스트 이벤트 보내기”. iPhone에서 Galaxy Relay 알림과 PWA 기록을 확인한다.

Apple Developer Program, 네이티브 iOS 앱, APNs certificate, App Store 심사는 필요하지 않다. [Apple Web Push 안내](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)를 참고한다.

## 사용

- 밝은 바탕과 불투명한 카드의 알림함을 표시한다. 시스템 다크 모드, 날짜별 구역, 읽지 않은 수, 연결 상태와 모바일 하단 상세/답장을 지원한다. [현재 디자인](inbox-design.md). iOS 시스템 Push 배너의 디자인을 바꾸는 기능은 아니다.
- 검색창과 전체/앱/문자/전화 분류가 항상 보인다. 앱·이름·본문을 검색할 수 있다.
- 상세를 실제로 열면 `read=true`로 표시하고 목록 및 IndexedDB `notifications`의 본문 기록을 유지한다. 읽지 않은 알림 개수에서는 제외되며 닫거나 새로고침해도 다시 열 수 있다. 상세 조회만으로 Galaxy 원본 알림을 제거하지 않는다.
- 삭제한 ID/시간·최소 상태는 `states`에 최대 5,000개 유지하여 동일 이벤트 재전송으로 삭제한 본문이 복원되지 않게 한다. 읽음 기록에는 삭제 tombstone을 만들지 않는다. 이전 버전에서 이미 지운 본문은 복원할 수 없다. 최소 상태도 ‘모든 알림 기록 삭제’에서 지워진다.
- 앱·발신자/채팅 제목별 묶음은 최신 알림과 개수 배지를 보여준다. 묶음을 누르면 전체 내용을 펼치고 ‘간략히 보기’로 다시 접는다. 정확한 채팅 ID를 원본 앱이 제공하지 않으므로 제공된 발신자/제목이 같으면 같은 묶음으로 간주하며, 정보가 없으면 앱 단위로 묶는다.
- 개별 알림을 누르면 상세를 표시하고 읽음 처리하되 기록은 남긴다. 그 상세 카드를 **다시 누르면** 원본 알림의 Galaxy 동작을 요청한다. OS 조건에 따라 Galaxy에서 사용자 확인 알림을 눌러야 한다. 원본이 사라졌거나 이전 갱신 기록이면 원본 열기를 제공하지 않는다.
- **왼쪽으로 충분히 밀기**: 개별/묶음의 PWA 기록을 지우고 해당 활성 Galaxy Notification의 DISMISS를 요청한다. 앱 메시지 읽음과 별개다. 하나의 Android Notification이 여러 갱신 기록의 원본이면 해당 Notification 제거에 연결된 기록도 함께 정리한다. 전화 기록·직접 SMS처럼 원본 Notification이 없는 항목은 로컬 기록만 지우며 통화를 거절하는 기능은 아니다.
- 짧은 밀기·세로 스크롤은 지우지 않는다. Delete 키도 같은 동작을 제공한다. 오프라인에서 원본 삭제가 필요한 항목은 기록을 유지하고 연결 후 다시 밀도록 안내한다. 즉시 FCM 접수 실패 시 남은 항목을 유지한다. FCM 접수 성공과 실제 기기의 실행 성공은 별개이며 기기 오프라인/강제 종료 시 원격 처리가 지연될 수 있다.
- 상세 후 재탭 열기를 유지하기 위해 **상세 조회 자동 ACK 옵션은 제거**했다. 기존 서버 설정이 ON이어도 새 PWA는 ACK를 보내지 않는다. 원본 삭제는 사용자의 스와이프에서만 요청한다.
- Galaxy에서 원본 알림을 지우거나 앱 확인으로 해당 Notification이 사라지면 PWA가 상태를 조회한 뒤 관련 기록을 삭제한다. 이미 상세를 연 카드만 화면에 임시 남아 제거 상태를 표시한다. 삭제·명령 결과 Push 배너는 만들지 않는다. 갱신 기록이 많을 때도 20개씩 돌아가며 상태를 조회한다.
- 서버의 제거 receipt TTL은 1시간이며 KV·네트워크·PWA 실행 제한에 따른 best-effort 동기화다. 오래 닫아 두거나 기기에서 제거 상태를 전송하지 못하면 완벽한 동기화는 보장하지 않는다. 원본 앱 서버의 읽음 상태 자체를 조회하는 기능은 없다.
- 명령 결과는 FCM 전달 접수와 별개다. 응답이 도착하기 전에는 요청 접수 상태를 표시한다.

## 1.1.0 알림과 전화

PWA를 인터넷 연결 상태에서 닫았다가 다시 연다. Galaxy에도 새 APK를 덮어 설치한다. 새 메시지 제목은 `김철수 · 카카오톡`, 전화는 `김철수 · 전화 수신` 또는 `01012345678 · 전화 수신` 형태다. PWA 이름·앱 아이콘은 Relay로 유지된다. 설정의 미리보기/이름 숨기기를 켜면 제목의 개인정보도 숨긴다.

통화 연결·거절·종료는 새 배너를 띄우지 않고 기존 수신 배너만 닫는다. PWA가 보일 때 통화·명령 대기 상태는 5초, 일반 상태는 15초 간격으로 조회하며 KV 전파·네트워크 지연이 추가될 수 있다. 다시 열거나 다음 메시지 Push를 받았을 때도 조회한다. 읽음 여부와 무관하게 남아 있는 통화 기록은 ‘통화 연결’ 또는 ‘전화 종료’로 변경한다. 사용자가 삭제한 기록은 복원하지 않으며, 상세가 열려 있는 동안에는 화면 상태도 갱신한다.

**PWA가 완전히 닫힌 동안에는 즉시 닫기를 보장할 수 없다.** [WebKit 정책](https://webkit.org/blog/16535/meet-declarative-web-push/)상 알림을 표시하지 않는 Push로 앱을 깨우면 구독이 취소될 수 있다. 종료 배너를 표시했다 바로 숨기는 우회도 사용하지 않는다. 따라서 조용한 동기화는 화면을 열었거나 실제 메시지 Push로 깨어난 기회에 수행한다. iOS가 `getNotifications()`로 제공하는 OS 알림만 회수할 수 있다.
- 오프라인에서도 기존 기록·검색·상세는 동작한다. 서버 명령은 비활성화한다.
- 기록 최대 5,000개. 오래된 기록부터 삭제한다. 전체 기록 삭제에는 확인 dialog가 있다.

## 개인정보·저장 공간

미리보기·본문·이름 숨기기는 각각 설정할 수 있다. IndexedDB는 브라우저 저장 공간이며 Secure Enclave와 같지 않다. iPhone 기기 잠금을 사용한다. Safari/PWA 저장 공간을 삭제하거나 OS가 공간을 회수하면 기록과 인증이 사라질 수 있다. 서버에 기록 복구 기능이 없으므로 기록을 보장되는 장기 백업으로 사용하지 않는다.

알림이 안 오면 iPhone 설정 → 알림 → Relay 권한, 집중 모드, 네트워크를 확인한다. Push subscription이 만료됐을 때는 홈 화면 PWA에서 “알림 활성화”를 다시 눌러 등록한다. 공유해서 받은 사이트 URL이 다르면 다른 origin의 저장 공간이므로 반드시 같은 주소를 사용한다.

## 연결 해제

선택형 E2EE는 기본 Push 성공을 확인한 뒤 [보안 가이드](security.md#e2ee-설정)대로 설정한다. 수신 키가 있으면 평문 Push를 거부한다. 키는 non-extractable CryptoKey로 로컬에 저장하며 서버로 보내지 않는다. 이 기능이 브라우저 전체 저장 공간이나 이전 본문 기록을 암호화하는 것은 아니다.

설정 → Galaxy 연결 해제 → 확인. Worker가 양쪽 인증·FCM metadata·subscription을 폐기하고 PWA는 로컬 Push subscription을 unsubscribe한다. 기록은 별도 “모든 알림 기록 삭제”에서 삭제한다. Galaxy에서 먼저 해제했을 경우 PWA의 다음 인증 요청이 거부되며 다시 연결해야 한다. Web Push 전달 지연과 KV 전파 때문에 이미 전송된 Push까지 즉시 회수하는 기능은 없다.

## 같은 앱을 두 기기에 설치한 경우

Relay는 iPhone의 다른 네이티브 앱(카카오톡, Instagram 등) 알림을 조회·삭제하거나 해당 앱에서 읽었는지 감지할 수 없다. Relay PWA가 만든 알림과 Galaxy Notification의 동기화만 제공한다. 같은 앱의 두 기기 알림 정리는 해당 앱 서비스가 자체 지원해야 한다. [Apple 알림 API](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/getdeliverednotifications(completionhandler:))는 자신의 앱 알림만 대상으로 한다.

## PWA에서 답장

Galaxy APK 1.2.0 업데이트 → PWA 종료/재실행 → 새 알림 상세 → 답장 입력/전송. 원본 알림이 답장을 지원하는 경우에만 입력창을 표시한다. Galaxy는 잠금 해제 상태여야 한다. 예전 E2EE 수신 키는 설정에서 같은 키를 다시 저장한다. [자세한 사용 방법과 제한](reply.md).
